# Fixes and shared foundations

Owner: the first builder, working on `main`. Read [00-overview.md](00-overview.md) first; its contracts are binding. Deliver a passing fixed-main commit before any feature worktree is created. Application work starts here, not in the planning commit.

## Goal and experience

The evaluator can run the application on this machine, report and edit an item with a photo, find it with filters, and manage claims without stale screens or silent failures. A signed-out visitor gets a clear login path; switching accounts cannot reveal the previous account's data. Approval honestly says "Awaiting pickup".

## Scope and decisions

1. Make Java reproducible. The audited Java 27/Lombok compile failed with `ExceptionInInitializerError: com.sun.tools.javac.tree.EndPosTable`. Default to a pinned Java 25 LTS toolchain supported by the selected Boot version, with source release 25 and a compatible pinned Lombok, since the code uses no Java 26 features. Install/provision it locally through a documented, checked bootstrap outside the repo; record the exact vendor/build and checksum. If compatibility evidence requires another supported JDK, record the reason and pin that exact build. Merely changing `java.version` while still running javac 27 does not fix annotation processing. A fresh shell must select the right JDK and build/test without the old target directory. Do not rely on undocumented shell state or global Java replacement.
2. Pin the Node/pnpm versions used successfully on this box and replace floating `latest` dependencies. Upgrade the TanStack family coherently and regenerate the lockfile. Audit previously found five critical entries, including GHSA-qx66-fv34-fjm8. Historical minimum patches are react-start 1.168.60 and start-server-core 1.169.39; verify current advisories and compatibility rather than assuming those fix everything. Remove unnecessary production tooling dependencies where appropriate. Zero critical advisories is a gate; record reachable remaining high findings and resolve the runtime ones. Never run a blind force-fix.
3. Environment-driven DB/JWT/storage/proxy/CORS configuration. Generate a new local JWT key outside Git, reject absent or weak signing material, and invalidate the old demo key. Commit only placeholder `.env.example` values. Keep known seed accounts behind an explicit local demo profile; remove the public admin-password box outside that profile. Baseline history preserves insecure demo defaults for reference; fixes must remove them from the current configuration before any deployment. Provide portless startup instructions/scripts that propagate the actual port/origin and work with Vite's port behavior. The audited naive portless wrapper selected one port while `pnpm dev` bound 3000; test the named URL, not just localhost.
4. Protect exact private routes before broad public GET matchers, including future item matches/question/edit endpoints as well as current claims, my-reports, and `/auth/me`. Reserve these rules now so feature branches never edit SecurityConfig. Supply JSON authentication/access-denied handlers, basic login/register rate limits, and correct malformed-input/missing-record mappings. Token expiry clears client auth and prompts login once without redirect loops. Validate restored auth through `/auth/me`; keep React hooks unconditional across hydration/logout and show a loading state while identity is unknown.
5. Implement the overview's lifecycle and locking in shared `ClaimWorkflow`. Approval on FOUND reserves; LOST-response approval completes its separate response flow. Remove the old automatic resolution on FOUND approval, enforce transitions on the server, preserve cancellation history, reject stale edits, and lock competing approvals. Reopening clears the timestamp only where permitted. Build tests against MariaDB, including two simultaneous approvals for one item and two found items competing for the same linked LOST report.
6. Remove contacts from public DTOs and associated TS/UI fields. Add the participant-only contact endpoint. Replace static query-client sharing on SSR, scope private keys to account ID, forward query abort signals, cancel/clear on login/logout/expiry, and centralize mutation invalidation. Private responses use `Cache-Control: no-store`. No contact details or secrets should be cached in a public DTO.
7. Add owner/admin report editing with length limits, allowed categories, date validation, and optimistic version checks. Preserve report type after creation and freeze edits during reservation; reject question changes while pending claims exist. Add location and status filters to the server and browse UI, URL-persisted search, clear-filters, and honest result counts. Default browsing to OPEN; authorized own/admin views still show terminal records.
8. Implement the photo contract from the overview with local, ignored storage. Attach existing photos safely and provide preview/remove controls, useful alt text, file validation, upload progress, failure recovery, and a fallback image. Failed upload must not pretend a report was saved. Limit uploads per account and clean unattached files on an explicit maintenance path.
9. Fill missing feedback on my reports, claims, admin queries/deletion, status changes, and claim decisions. Keep input after errors; announce success/errors accessibly. Preserve the intended item/report URL through login. Replace false notification text with statements about the saved claim until real notifications are present. Fix Base UI link/button semantics observed in dev warnings. Keep the present visual language and improve mobile controls, empty states, status labels, and loading consistency.

Implement the shared Item/Claim additions, status enums, DTOs, event records, query helpers, workflow operations, and both optional evidence adapter contracts in the overview. Core services publish committed-change events for create/edit/status/claim operations. Supply inactive frontend feature entrypoints at the exact owned paths and wire their controlled props/validity into create/edit/detail/header forms. Feature directories initially contain only the contract types/empty UI entrypoints needed for independent builds. Do not add fake matching results, successful alert APIs, OTPs, or ownership acceptance. A question-bearing claim without its policy fails closed. Actual feature endpoints remain owned by their feature builders.

Back up before migration. Verify new tables/columns against MariaDB and preserve counts and IDs. Feature migrations must also work in the documented merge order. Use a shared serialization/mapper for public item summaries so new endpoints cannot accidentally restore contact fields.

Update README with exact setup, fresh build, demo profile, database isolation, photo directory, secret generation, portless commands, test commands, and reset instructions scoped to a disposable demo DB. Add a verification script or documented executable API smoke flow. This shared verification and the seed runner remain fixes/lead-owned.

## Acceptance and proof

- A clean checkout plus documented bootstrap builds and tests on this box. Record JDK, Maven wrapper, Node, and pnpm versions. Run `timeout 180 ./mvnw clean verify`, frozen install, frontend typecheck/build, and dependency audit. Retry a cold dependency download separately if its timeout is environmental; report it accurately.
- Through the portless URL: register/login, create a photo report, edit it, filter by location/status, submit/cancel/retry a claim, approve/reject, inspect authorized contact, and log out. Revisit with a second account and confirm no previous data flashes or persists.
- Anonymous private reads return 401; strangers receive 403/404; malformed enum returns 400. Test expired tokens, duplicate claims, concurrent approvals, release, manual resolution, closed/deleted reports, and reserved edit/delete attempts. Verify all mutations refresh dependent views.
- Inspect public JSON and rendered HTML for email, phone, ownership evidence, signing keys, and private cache data. Test fake/oversized/path-traversal uploads and access to unattached images. Check contacts after cancellation are denied.
- Existing-schema upgrade preserves data; fresh migration/seed is repeatable. Legacy completed claims carry no verified badge. All four feature entrypoints compile independently and no unavailable feature is advertised.

Return the fixed-main SHA, shared API/type entrypoint locations, migration procedure, test results, and any acknowledged high-severity dependency exception. The lead freezes that SHA only after these gates pass.
